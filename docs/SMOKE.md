# 真实模型冒烟测试(make smoke)——零基础运行说明(macOS)

这个测试用来确认:**用你自己的阿里云百炼(DashScope)API key,系统能真正调用通义千问(Qwen)视觉模型给图片打标签**,
并且标签符合规范。它会自动完成,你只需要粘贴一次 key。

## 它会做什么、不会做什么

- ✅ 在 Docker 里另起一个**全新、独立**的数据库(项目名 `assetlib-smoke`),测完自动删除。
- ✅ 用示例行业包生成 13 张程序绘制的插画(12 张图库插画 + 1 张断网兜底样本,不是任何真实照片),挑图库里的 3 张上传,让真实 Qwen 打标签。
- ✅ 检查标签是否都在词表内、来源是不是真实 Qwen、提示词版本对不对,并用表格打印出来。
- ✅ 再故意用一个**错误的 key** 试一次,确认会明确报错、不会偷偷用假数据糊弄你。
- ✅ 结束后按 key 的原文扫描整个项目文件夹,确认 key 没有被写进任何文件。
- ❌ **不会**碰你电脑上已有的任何数据库;**不会**把 key 写进任何文件(包括 `.env`);屏幕上不会显示 key 原文(只显示打码后的样子)。
- 💰 会产生**少量真实调用费用**(3 次图片打标,通常远低于 1 元)。请确认你的百炼账号有可用额度。

## 一、准备(只需做一次)

1. **命令行工具**(git / make / python3 / curl):打开「终端」(启动台 → 其他 → 终端),运行:
   ```bash
   xcode-select --install
   ```
   弹出窗口点「安装」,等几分钟。已经装过会提示 already installed,不用管。
2. **Docker**:安装并**打开** [Docker Desktop](https://www.docker.com/products/docker-desktop/)(或 [OrbStack](https://orbstack.dev)),
   首次打开按提示完成设置,等菜单栏的鲸鱼图标停止转动,表示已在运行。
3. **百炼 API key**:登录[阿里云百炼控制台](https://bailian.console.aliyun.com/) → 右上角/侧栏找到「API-KEY」→ 创建并复制。
   key 一般以 `sk-` 开头。请当作密码保管,**不要发给任何人、不要写进聊天记录**。
4. **拿到项目代码**:
   ```bash
   git clone https://github.com/zhangleo-1983/studio-asset-library.git
   cd studio-asset-library
   ```

## 二、运行

在项目文件夹里执行:

```bash
make smoke
```

然后按屏幕提示:

1. 程序先检查环境;缺什么会用中文告诉你怎么装,然后退出——装好后重新运行即可。
2. 出现 `DashScope key:` 时,**粘贴你的 key 并回车**。粘贴时屏幕上看不到任何字符,这是正常的(为了安全)。
3. 等待。第一次运行要下载 Docker 镜像,可能需要几分钟;之后每次约 1–3 分钟。
4. 最后会看到「汇总」和「总结论」。

## 三、怎么看结果

汇总里每一项前面是 ✅(通过)或 ❌(没通过),最后一行是 **总结论:✅ 通过 / ❌ 未通过**。

| 检查项 | 含义 |
|---|---|
| 已确认不是 mock 模式 | 没有开启任何“假数据”开关;服务以严格模式运行 |
| 全新数据库与服务已启动 | 独立环境启动成功 |
| 演示素材已生成 | 示例包生成了 12 张图库插画 + 1 张断网兜底样本(共 13 张;测试只上传图库里的 3 张) |
| 3 张图都通过 API 上传并由真实 Qwen 打标成功 | 真实调用成功 |
| 每张图都产出了标签 / 都在词表内 / 来源是真实 Qwen / 提示词版本是 tagging_v3 | 逐项断言;上方表格列出每张图的每个标签 |
| 错误 key 得到明确报错 | 反向测试通过:错的 key 一定会失败,不会悄悄退回假数据 |
| 已清理测试容器与数据库 | 用完即删 |
| key 没有落进工作区的任何文件 | 安全检查通过 |

### 哪些标签"在词表内",哪些不受词表约束

示例包(balloon)有 5 个维度,**只有 3 个受词表约束**:

| 维度 | 类型 | 检查 |
|---|---|---|
| 造型、配色、场景 | 受词表约束(模型输出必须能对应到词表里的词,否则记为"待归类") | ✅ 本测试逐条断言必须在词表内(状态"在册") |
| 主题、配色简称 | **自由文本**(模型想写什么就写什么,如「爱心」「红白黄」) | 本测试**不检查**词表,只检查有没有标签、来源和提示词版本 |

所以表格里"配色简称"这类标签(如「红白黄」)不在任何词表里是**正常的**,不代表出错。另外:
- 本测试**只验证流程与规范,不评判标签是否"准确"**(例如把红金配色的图标成"红白黄"、场景标成"其他",测试仍算通过——准确率请另行评估)。
- 场景词表里含"其他",模型拿不准时选它算"在词表内"。

## 四、常见问题

| 现象 | 怎么办 |
|---|---|
| 提示 Docker 没有运行 | 打开 Docker Desktop(或 OrbStack),等它完全启动后重试 |
| 提示 key 无效(401) | 重新复制 key,注意别多复制空格;确认是**百炼**的 API key,且未被禁用/过期 |
| 上传失败,提示额度/网络 | 检查百炼账号余额与免费额度、网络是否能访问 `dashscope.aliyuncs.com` |
| 某项标签不在词表内(❌) | 真实模型偶尔会输出词表外的词;表格里会列出是哪个词。重跑一次通常会好;若反复出现,请把结果告诉维护者 |
| 提示端口被占用 | 本测试使用随机空闲端口,一般不会冲突;若仍报错请重试 |
| 提示在某文件里发现了 key | 说明这个 key 出现在了项目文件夹的某个文件里(比如你之前把它写进过 `.env`)。**本测试从不写入文件**;请删除该文件里的 key,并到百炼控制台**重置**这个 key |
| 测试中途按了 Ctrl+C | 程序会自动清理;若仍有残留,手动运行 `docker compose -p assetlib-smoke down -v` |

## 五、给开发者的说明

- 入口:`make smoke` → `scripts/smoke.sh`(bash 3.2 兼容)+ `scripts/smoke_check.py`(断言与表格,仅标准库)。
- `make demo-assets` 使用宿主机 `.venv`;本测试为免安装 Python 依赖,在容器内运行**同一条命令**(`scripts/pack_run.py assets`)。
- 严格模式:demo 服务加 `DEMO_STRICT=1`(见 `app/demo/server.py`)——禁止 mock/离线兜底,真实调用失败直接返回 HTTP 502 + 错误信息(已对 key 打码),不再静默降级。
- 来源断言依据 `task.output._provider`(真实调用为 `qwen`,mock 为 `mock`),不是模型名。
- 单张图的开发者冒烟仍保留为 `make smoke-single IMAGE=/path/to.jpg`(使用 `.env` 里的 key)。
