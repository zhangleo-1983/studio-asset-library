## 近期方向(对应「已知局限」)

| 方向 | 现状 | 打算怎么做 | 已留的位置 |
|---|---|---|---|
| **以图搜图** | 目前只有标签检索(标签重合度召回);没有向量/语义相似检索 | 需要时旁挂向量库,用图像嵌入做"以图搜图/语义相似",与标签检索并存,**不改主表** | `tag` 规范化表 + GIN 索引;检索与存储解耦 |
| **自定义维度** | 维度键固定为 5 个(`structure` / `color` / `scene` / `theme` / `color_scheme`);行业包只能选用、换词表、改展示名 | 新迁移:把维度定义落成表,并把 `tag_role_shape`、`tag_provenance_by_source` 两条 CHECK 改为不依赖维度键;行业包 `taxonomy.json` 随之放开维度键与 role | 行业包机制与校验已就绪,见 [industry-packs.md](./industry-packs.md)「已知限制」 |
| **compose 部署真实打标** | compose 里的 worker 是占位(空转),也未传入 `DASHSCOPE_API_KEY`;真实调用目前只在 `make smoke` 中验证过 | 实现 worker 的真实处理(领取 pending 任务 → 调用 → 落标签),compose 传入密钥(经环境变量/密钥文件,不入镜像) | 任务队列走 PG(`FOR UPDATE SKIP LOCKED`)、`run_batch` 已实现;缺的是常驻 worker 与密钥注入 |
| **自由文本维度归一化** | 主题、配色简称是自由文本,不受词表约束,可能"同义不同写" | 提供可选的归一化:别名合并、相似词聚类建议进入复核队列,由人确认后并入词表或别名 | 别名表 `alias_map`、词表版本机制、复核队列 |
| **真实照片准确率评测** | 示例包素材是程序绘制的插画;`make smoke` 只验证流程与规范,不评估准确率 | 提供评测脚本与小型公开评测流程(用户自备带人工标注的真实照片),输出各维度准确率与词表外率 | `config_version` 可版本化配置,便于模型/提示词 A/B |

## 其他后续能力(留位,暂不做)

| 后续能力 | 为何暂不做 | 数据结构已留的位置 | 触发条件 |
|---|---|---|---|
| **自助租户开通** | 目前由部署方用种子脚本建租户 | `tenant` 表、全表 `tenant_id`、租户中间件 | 出现需要自助入驻的多个租户 |
| **多语言** | 词表目前只填中文 | `vocabulary.labels` JSONB(`{"zh":…}` → `{"zh":…,"en":…}`),翻译在词表层【不变量三】 | 出现跨语言使用需求 |
| **第二种任务类型**(如物料拆解) | 尚无真实需求 | `task.task_type` 开放列 + `output`(JSONB)+ `output_schema_version`【不变量四】 | 有真实需求 |
| **配置审批流** | 目前保存配置即自动生效(效率模式) | `active_config` 显式生效指针;审批模式在指针前加"待生效/已批准"闸门即可 | 有团队协作与审批需求 |
| **按量计量的展示** | token 用量已从第一天落进溯源 | 按租户聚合即用量底稿;需要时补一个查看界面,不补数据【不变量二】 | 有用量展示需求 |

## 承重结构如何支撑扩展(不需返工)

- **第二种任务** = 新增一个 `task_type` 常量 + 一套 `output` schema + 一个执行函数,`task` / `tag` / `event` 表零改动;不建插件框架。【不变量四】
- **第 N 个租户** = 每行数据已带 `tenant_id`,新增租户即插入一行 `tenant` + 用户;要求物理隔离则复制一套部署,业务代码零改动。【不变量一、三】
- **换存储 / 冷备** = 只改 `StorageBackend` 实现,业务通过 `asset_id` 访问,零感知。【不变量三】

> 本文不构成实现承诺;实际优先级取决于使用者的真实需求。
