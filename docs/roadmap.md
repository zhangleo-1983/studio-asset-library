## 第一期明确不做,及其"留位"方式

| 后续能力 | 本期为何不做 | 数据结构已留的位置 | 触发条件(何时才做) |
|---|---|---|---|
| **自助租户开通** | 单租户交付,无自助需求;做了就诱导建租户管理界面 | `tenant` 表结构、全表 `tenant_id`、租户中间件 | 出现第 2、3 个需自助入驻的租户 |
| **模板装修** | 属租户自助管理界面,违背交付纪律 | — | 明确的多租户品牌定制需求 |
| **小程序代生成** | 一次性交付即可,不做生成器 | — | 需要给多个租户各自出小程序时 |
| **拆检 bom_extract** | 第二种任务类型尚无真实需求 | `task.task_type` 开放列 + `output`(JSONB)+ `output_schema_version`;新增即加值加 schema,核心表不动【不变量四】 | 有真实拆检/物料清单需求 |
| **供应链对接** | 选款 SaaS 本期只解决"找参考图",不接采购 | 事件流水可承载选款→采购的行为记录 | 选款闭环稳定后,客户提出采购对接 |
| **向量检索** | 标签过滤已满足多维交叉筛选类查询,数万张规模用不上向量【隔断墙】 | `tag` 规范化表 + GIN 索引;需要时旁挂向量库,不改主表 | 出现标签无法表达的"以图搜图/语义相似"需求且规模上量 |
| **多语言** | 首个租户中文即可 | `vocabulary.labels` JSONB 概念级留位(`{"zh":…}` → 未来 `{"zh":…,"en":…}`);翻译在词表层不在数据层【不变量三】 | 出现跨语言租户/海外行业 |
| **评测能力回迁** | 旧项目 judge/score/acceptance 是评测期工具 | `config_version` 可版本化配置,便于 A/B | 需要在平台内做模型/提示词回归评测 |
| **配置"质量模式开关 + 租户内审批流"**【OQ-1/裁决七】 | 本期效率模式:保存配置即自动推指针,无审批 | `active_config` 显式生效指针机制(推指针 = UPDATE 指针 + `config_activate` 事件);审批模式在此指针前加"待生效/已批准"闸门即可,不改承重结构 | 租户提出配置审批需求 |

## 承重结构如何支撑扩展(不需返工的证明)

- **第二种任务(如 bom_extract)** = 新增一个 `task_type` 常量 + 一套 `output` schema + 一个执行函数。`task` / `tag` / `event` 表零改动。**不建插件框架、编排系统、引擎市场**——宪法不变量四"禁止"条款。第三种真实任务出现前,不建任何框架。
- **第 N 个租户** = 数据层每行已带 `tenant_id`,新增租户即插入一行 `tenant` + 用户;要求物理独立则复制一套部署,业务代码零改动。【不变量一、三】
- **换存储 / 冷备 / 单租户独立部署** = 只改 `StorageBackend` 实现,业务通过 `asset_id` 访问,零感知。【不变量三】
- **按量计费** = token 用量从第一天就落进溯源,按租户聚合即计费底稿;要收费时补一个 UI,不补数据。【不变量二】

## 阶段划分(粗粒度,顺序可调)

1. **一期(当前):** 单租户,资产入库 + 打标 + 词表/回流 + 两端 + 导出。见 [architecture.md](./architecture.md) §7。
2. **二期候选:** 多人协作与权限细化、评测能力回迁、复核体验优化。
3. **三期候选:** 第二种 task_type(拆检/审图之一,视真实需求)、多租户自助化、供应链对接的第一步。

> 二、三期均需真实需求触发并重新评审;本文不构成实现承诺。
